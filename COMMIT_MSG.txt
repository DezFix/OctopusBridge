Release 7.36: Ren'Py 69.2% (было 49.8%), модуль Godot

Ren'Py — потеря была не в переводчике, а в разборе. Узел Label при
обходе .rpyc проглатывался без имени, поэтому текст скомпилированных
игр терял метку, а запись без метки не попадает ни в один блок
перевода: никуда. Метка восстанавливается на обходе AST и привязывается
к блоку своего узла, а не «помнит» последнюю метку файла.

Решение «писать / не писать» теперь по виду УЗЛА, а не по виду текста:
Say/TranslateSay/Menu/Screen (включая имя персонажа Say.who) — берутся,
это отображаемый текст; Define/Default/Python/python:/$ — не берутся
никогда, это литералы внутри выражения, то есть ключи, которые игра
ищет сама. translate <lang> strings: не возвращался — он подменяет
python-строки прямо в коде игры, именно это ломало SR24.

Покрытие на реальных играх: SR24 49.8% -> 69.2% (4426 в метках + 113
экранов из 6562), Shoretown Saga 99.5% (5067 из 5090). Непереведённое
больше не молчит: skipped_by с причинами по контракту ApplyReport.

Godot — новое ядро (app/core/godot): чтение/разбор/потоковая пересборка
.pck, detect/extract/apply/restore_original/verify. Формат сверен с
исходником движка, не с вебом: v2 (4.0-4.3) и v3 (4.5+), где вместо
reserved[16] лежит dir_offset и file_count читается после seek. Проверено
чтением на реальной игре Godot 4.6 (13271 файл, v3, md5 40/40).

Главное в защите — два бага, найденные ревью и закрытые:
- прерванный бэкап .pck оставался на диске и при откате сокращал файл с
  172 до 10 байт, игра не запускалась, оригинала нигде не было. Теперь
  копия идёт через временный файл, размер сверяется ДО os.replace.
- verify не читал байты блобов: смещение, уехавшее на байт, давало
  «успех» при битой игре. Теперь блоб читается потоком и сверяется md5.

Тесты формата .pck были тавтологичны (константа сравнивалась сама с
собой, round-trip через собственный же writer) — добавлен независимый
разбор заголовка сырым struct.unpack_from по смещениям из fap.cpp.
