# ЧАСТЬ 1. КАРТА ПРОЕКТА

## 1.1 Общее

| Параметр | Значение |
|---|---|
| Имя | OctopusBridge |
| Назначение | Перевод игр (внутриигровой текст) + живые читы |
| Язык / UI | Python 3, PySide6 |
| Лицензия | GPL-3.0 |
| Репозиторий | `github.com/DezFix/OctopusBridge` |
| Ветка разработки | `main` |
| Замороженная ветка | `archive/octopus-8` (снапшот переработки 8.0, откатан на 7.x) |
| Версия в коде | `app/__init__.py::__version__` |
| Тестов | 21 файл в `tests/`, запуск — `python run_tests.py` |
| Размер кода | ~37 400 строк в `app/` |

**frida**, pywebview, **UnityPy**, TypeTreeGeneratorAPI; для сборки —
pyinstaller.

## 1.2 Слои и правило зависимостей

```
app/core        чистая логика, БЕЗ Qt          ~парсеры, io, translate
     ↓
app/engines     движковые модули, БЕЗ Qt        detect / extract / apply / features
     ↓
app/live        живые сессии (Qt)               Tentacle, GameSession
     ↓
app/transport   код транспортов                 cdp/ (Chromium), frida_rpc/
     ↓
app/ui          виджеты, вкладки, i18n          единственное место с Qt

Движки соединяются с live-слоем **только строкой `key`**
(`app/live/__init__.py::create_tentacle`).

## 1.4 Как работает перевод (конвейер)

1. **Detect.** `detect_engine()` спрашивает все включённые модули, берёт
   максимальный вес. Unity весит 95 при наличии `*_Data/Managed`,
   `globalgamemanagers`, `level*`, exe.
2. **Extract.** `module.extract(game_dir)` → `list[TranslationEntry]`.
   Unity: `TextAsset.m_Script`, `MonoBehaviour` (по allow-list хинтов),
   `TextMesh/GUIText.m_Text`, `TextMeshPro*/m_text`,
   StreamingAssets (`.json/.csv/.txt`).
3. **Translate.** `app/core/translate/service.py` — rotate-пул
   Google → Bing → MyMemory. `_resolve_src()` определяет язык строки
   (смешанные игры), `mask()` прячет крайние коды, глоссарий режет по терминам.
4. **Apply.** `module.apply(game_dir, entries, target_lang=...)`.
   Порядок для файлов игры: `BackupStore` → `atomic_write_bytes` → verify
   перечитыванием. Unity дополнительно сверяет текущее значение с `original`
   и **пропускает** строку при расхождении.

## 1.5 Как устроены «живые» читы

- **RPG Maker.** MZ/Electron — CDP с `--remote-debugging-port`.
  MV без SDK — инъекция `octopus_ob.js` в игру (свой HTTP-мост).
  JS-компилятор чит-выражений — `_cheat_expr`.
  Умеет: золото, скорость, лечение, снятие состояний, победа в бою,
  ноклип, телепорт по клику, скорость, перезагрузка карты, предметы,
  актёры, переменные/переключатели, запуск событий, открытие меню.
  Под мостом MV `send_key` и `screenshot()` **недоступны** — честно `False`.
- **Ren'Py.** При старте пишется `game/ob_agent.rpy` (py2/py3 по версии),
  агент поднимает TCP-сервер. Если игра уже запущена — bootstrap через
  `PythonInjector` (Frida) с offsets по версии.
  Умеет: золото, лечение, переменные по имени, телепорт по label,
  `exec` (произвольный код), шрифт/размер шрифта. **Плюс файловый режим**
  по сейвам — работает вообще без запущенной игры.
- **Twine / HTML.** Свой HTTP-сервер + JS-инъекция + WebSocket.
  Умеет: `var_set` (SugarCube/Harlowe, с созданием промежуточных объектов),
  `exec` = `eval`, сохранение/загрузка сейвов.
- **Unity / Wolf.** Канала нет. Только запуск/останов процесса.

### 1.5A. Unity: файловые читы (без канала в процесс)

Канал в процесс Unity запрещён правилами проекта. Поэтому читы Unity —
правка того, что игра сама пишет на диск/в реестр:

| Источник | Путь | Что редактируем |
|---|---|---|
| PlayerPrefs | `HKCU\Software\<company>\<product>` | int / float / string / байты |
| JSON-сохранения | `%USERPROFILE%\AppData\LocalLow\<company>\<product>\*.json` (и верхний уровень папки игры) | плоские числа, флаги, строки по точечным путям |

- Ветка реестра выводится из `globalgamemanagers` (`companyName`,
  `productName`), а не угадывается — движок работает с чужой игрой.
- Типы Unity: `REG_DWORD` → int, `REG_SZ` → строка, `REG_BINARY` длиной 4 →
  float, иначе произвольные данные.
- К имени ключа Unity дописывает хеш `_h<число>`; для показа он срезается,
  при записи возвращается.
- Служебные ключи (`unity.*`, `Unity*`, `Screenmanager*`) помечены, но видны:
  спрятать = потерять кнопки, которые несут загруз игры.
- `app/core/unity/json_save.py`: пишем только изменённые листья, бэкап до,
  самопроверка чтением после, откат при расхождении, тип исходного значения
  — закон (`bool` не становится `0/1`, `float` — `int`).

## 1.7 Известные ограничения (осознанные, не баги)

1. **Unity — только Mono.** IL2CPP-игры (`GameAssembly.dll`) не читаются.
2. **Unity TMP SDF-шрифты не патчатся.** Генерация атласа требует Unity
   Editor. Считаются в `stats['tmp_fonts']` и честно показываются.
3. **Unity — нет канала в процесс игры.** Правилом запрещена инъекция
   (см. `AGENTS.md` §1).
4. **CDP только для Chromium-подобных хостов.** Unity-игры CDP не подходят.
5. **В игру лезть нельзя** — общее правило проекта.

## 2026-10-08 — Unity: перевод наконец виден в игре (v7.30)

**Симптом.** Пользователь: «в Unity игра не переводится». Переводчик при этом
работает, а остальные парсеры/модули проблем не показали.

**Ход расследования.**

1. `detect` на реальной игре (`E:\Temp\IDM\GakkodeG_v1.00_Uncensored`)
   вернул 95 — детект в порядке.
2. `extract` — **6951 строка**, 26 файлов-кандидатов, 488 113 объектов,
   14 000 текстовых объектов, typetree `ok`. Извлечение работает.
3. `apply` по всей игре — **14 файлов, 6951 строка, `verify_failed: 0`**,
   повторный `extract` показывает все 6951 помеченных строк. **Внедрение
   тоже работает.**

Значит, чинить переводчик — нечего. Перевод в файлы доходит; не видно его
в игре.

4. Осмотр шрифтов игры: `Font` ×2,
   `PerfectDOSVGA437` и `MochiyPopOne-OTF-ExtraBold`, у обоих
   **`m_FontNames` непустой** — это **динамические OS-шрифты**.
   Для них Unity рисует текст системным файлом по имени и
   **игнорирует `m_FontData`**.

**Причина.** Подмена шрифта была фиктивной. Перевод записан корректно, но
кириллица после перевода выводилась пустыми квадратами (шрифты без кириллицы:
японский и DOS-шрифт). То есть «не переводится» = «переведено, но нечитаемо».

Дополнительно: **кнопки замены шрифта для Unity в UI не было вообще** —
ряд «Кириллица» на дашборде показывался только для RPG Maker / Ren'Py / Wolf
(`welcome_tab.py`, `cyr_supported`), а `UnityModule.font_patch` был
недостижим из интерфейса; при этом кнопка уходила в ветку Ren'Py.

**Исправление.**

- `app/core/unity/parser.py::font_patch` — при непустом `m_FontNames`
  список обнуляется (шрифт становится статическим и берёт текст из внедрённых
  данных). Счётчик `stats['dynamic_neutralized']`.
- `app/core/unity/parser.py::is_patched()` — честная проверка бэкапов для
  показа кнопки отката; `app/core/io.py::BackupStore.manifest_files()`.
- `app/ui/welcome_tab.py` — `unity` добавлен в `cyr_supported`; ветки
  `unity` в `_font_patch`, `_font_patch_choose`, `_font_restore`
  (`restore_original`).
- `app/ui/i18n.py` — ключ `res_font_done_unity` (ru/en).

**Проверка на реальной игре.** `font_patch`: `fonts=2, files=2,
verified=2, dynamic_neutralized=2`. Повторное чтение ассетов: оба шрифта
`m_FontNames = []`, `m_FontData` = NotoSans (9 589 900 Б). Откат через
`BackupStore.restore_all()` возвращает оригиналы.

**Тесты.** `tests/test_unity_new.py`: п.2 (нейтрализация динамического
шрифта), новый п.2b (статический шрифт не трогаем, TMP считается,
`is_patched`/`restore_all`), новый п.6b — guarded-блок по реальной игре,
фиксирующий, что оба её шрифта динамические (иначе регрессия вернётся
молча).

**Про читы Unity — решение шефа.** Субагент предложил реализовать читы
через Frida-инъекцию в процесс (`mono_domain_get` и т. п.). Шеф отклонил:
**в игру лезть нельзя**. Поэтому читы Unity, если будут, делаются
**только файлами** (PlayerPrefs/сейвы/значения в ассетах), без канала
в процесс. Отчёт по архитектуре читов приложен к этому же разбору —
см. §1.5 и ниже.

**Итоговая картина «читы не работают».** Для Unity читы не сломаны — их
никогда не было и не должно быть без канала. Три независимых замка,
открывать надо все: `features` (только автозапуск) → ветка в `build_tabs()`
(существование вкладки) → `is_attached()` (рабочий канал). Проверено
чтением кода: `UnityTentacle` наследует базовый `Tentacle`, `is_attached()`
возвращает `False`, `attach()` всегда ошибку, в `build_tabs()` ветки
`unity` нет.

## 2026-10-10 (ночь-7) — читы для ЛЮБОЙ HTML-игры

Шеф: «но оно только для twine, а не для любой html игры. А если для
любой выйдет?»

Вышло. И по дороге нашлись ещё три бага, из-за которых у обычных HTML-игр
читов не было вообще.

### 1. Что сделано

Мост вклеивается в страницу и у HTML-игр тем же кодом (`PAYLOAD_SCRIPT`),
и `request_vars` там уже был. Но про движок чужой игры мы не знаем ничего,
поэтому вместо угадывания — смотрим на окно страницы и берём объекты,
похожие на данные игры: свои, небольшие, с простыми значениями. В списке
они с префиксом `page.`, правятся точечно.

### 2. Три бага, найденных проверкой на живой странице

Проверил на обычной HTML-игре (никакого SugarCube/Harlowe) в браузере:

1. **У HTML-движка не было записи.** `set_variable` был заглушкой с
   честным `False`, а `_on_ws_message` не обрабатывал `cheat_ack` — то
   есть запись и не ушла бы, и даже если бы ушла, вкладка молчала бы.
2. **Срез пути `page.*` был на один сегмент вместо двух** — имя объекта
   подставлялось в путь дважды, и правка уходила в никуда.
3. **В список лез мусор браузера**: `GPUBufferUsage.*`,
   `GPUColorWrite.*`, `event.isTrusted`, таблицы WebGL-констант. Первая
   версия фильтра дала 63 строки, из которых настоящими были 7.

### 3. Результат проверки

Обычная HTML-игра, объявлено `gameState` и `player`:

```

   page.gameState.level = 3        page.player.mana  = 30
   page.gameState.hero  = "Ivan"   page.player.buffs = ["rage","haste"]
   page.gameState.paused = false
объекты-библиотеки отсеяны: True True
запись page.gameState.coins = 777 -> ack ok=True

## 2026-10-10 (ночь-6) — Twine: мгновенный/медленный перевод + читы

Шеф: «странно что какой-то перевод моментальный а какой-то появляется
через время + нету читов, прошлый разраб не сделал. Нужно что-то
придумать, либо лайв либо чит. Изучи, придумай как лучше».

### 1. Ответ на вопрос «live или чит»

Live, и однозначно. Игра Twine — это страница в браузере, а переменные
лежат в обычном JS-объекте (`State.variables`). Правка файла сейва
требует «загрузить сейв», не видит текущего состояния (счётчики,
флаги, то, что ещё не сохранено) и, как показала практика с Unity,
ломает игру. Живая правка видна сразу и не может сломать файл.

### 2. Почему перевод то мгновенный, то с задержкой

Так и устроено: строка уже в словаре проекта или в памяти сессии →
мгновенно; новая строка → поход в Google → задержка. Само по себе это
нормально. **Но результат нигде не сохранялся**: `_live_translate`
просто возвращал перевод, `push_tr_dict` никем не вызывался. Поэтому
каждый новый запуск игры — снова сеть, снова задержки, снова «половина
сразу, половина потом».

Сделал `app/core/twine/live_tr.py` — память переводов по играм
(атомарная запись, изоляция по пути игры, битый файл = пусто). Важная
деталь: НЕ пишем в проект `.ob.json` — его держит вкладка перевода, и
подмена из WS-потока портила бы файл. Первая версия ещё копила записи с
окном 10 секунд; в медленной игре переводы просто терялись бы, поэтому
окно убрал — пишем сразу.

### 3. Почему «читов нет» — и почему прошлый разраб их не сделал

Мост был, и он **работал**. Но на живой игре был мёртвым. Причина:

```js
__OT._fmt = (function(){ if (typeof State !== 'undefined' ...) })();
```

Формат вычислялся ОДИН раз в момент внедрения скрипта. А мост вклеивается
в начало документа, а движок истории грузится позже — на тот момент
`State` и `Harlowe` ещё не существуют, `fmt` навсегда оставался
`unknown`, и `collectState()`/`setVar()` молча отдавали пустоту. Отсюда
и «половина работает, половина нет».

Заменено на ленивое определение: `__OT.fmt()` и `__OT.varsRoot()`
вызываются в момент обращения. Заодно добавлен SugarCube 2
(`SugarCube.State`) — у него состояние не в глобальном `State`.
`setVar` больше не создаёт путь на лету: опечатка отклоняется, а не
молча создаёт новую переменную.

Проверено на живой странице в браузере (мини-история SugarCube,
настоящий HTTP-инжект и WebSocket приложения): прочитано 8 переменных,
`gold = 9999` записано и подтверждено САМИМ сообщением игры
(`state: {'gold': 9999}`), неизвестное имя отклонено.

### 4. Регресс

`tests/test_twine_bridge.py` — формат не вычисляется при внедрении,
нет обращений к мёртвому `__OT._fmt`, есть SugarCube 2, `setVar`
отказывает на мусоре и перерисовывает игру; плюс память переводов
(накопление, отсутствие потерь, изоляция, битый файл).

## 2026-10-10 (ночь-3) — читы пустые + нет выбора сейва

### 1. Читы: причина была не в сигнатуре RPC

Прошлый раз я решил, что дело в payload-конвенции, и починил подписи.
Проверка на живой игре показала: подписи были ни при чём. Один запуск,

- `assemblies()` → 119 сборок, игра — `Assembly-CSharp` **без `.dll`**;

1. **Не кэшировались `NativeFunction`.** Агент создавал их заново на
   каждый вызов. Сборщик мусора Frida успевал убрать объект посреди

   было ключевое отличие. Кэш `NF[key]`, все обёртки через `fn()`.

   поля SaveHub давали ОДИН адрес. Смещения при этом правильные и
   похожи на раскладку статик-блока (0, 8, 16, 20, 24). Отсюда адрес
   = база + `mono_field_get_offset(f)`. Проверено: до правки
   `<VolumeMaster>k__BackingField` = 1.4012984643e-45 — это бит-образ
   int `1`, прочитанный по чужому адресу; после правки 0.333, 0.425 —
   совпадает с `volumeMaster` из save.json.

Про `mono_thread_attach`: я подозревал его отсутствие, но проба
показала — `mono_class_vtable` работает и без него. Гипотеза не
подтвердилась, код оставлен как страховка.

Проверено вживую: **187 статических полей за 0.02 с**, запись
прочитала-изменила-проверила-вернула (`SaveHub.<VolumeSystem>` 
0.4416 → 0.75 → 0.4416), несуществующее поле отказало вежливо, игра
жива.

### 2. Переподключение не делало ни одной попытки

`attach()` к уже запущенной игре вызывал `_attach_rpc`, где проверка
«жив ли процесс» смотрела на `self._proc`. При `attach()` Popen'а нет →
`alive = False` → цикл выходил до первой попытки. Теперь при отсутствии
Popen alive берётся из реестра.

Факт по диску: эта игра пишет **один** `save.json` (35 ключей верхнего

таблицу: имя файла было только текстом в строке, выбрать слот было
нечем.

Добавлен список файлов: «Все файлы (N)» + каждый файл отдельно,
одинаковые имена различаются папкой (`slot3 / save.json`), в общем
списке имя файла есть в строке. Один файл — выбор скрыт.

[2, 11, 12, 13, 14, 15], выбор slot3 → его 147 строк и ref в slot3.

`tests/test_unity_agent.py` — 6 проверок контракта агента: кэш

## 2026-10-09 — live-читы Unity (7.31): входим только в свои процессы

Шеф, протестировав сборку 7.30, вернулся к читам: перевод есть, играется,
но «про читы не понял — то есть нет и не будет?». Формулировка надписи
(`unity_cheats_note`: «Живого канала в процесс Unity нет — и не будет»)
отправляла читателя не туда: она заявляла политику, а не факт.

Два вывода, которые я сделал сразу:

1. **Файловые читы уже существовали** (7.30): PlayerPrefs + JSON-сейвы,
   вкладка «Читы» у Unity. Не было только live-канала.
2. **Надпись врала форматом**: «и не будет» — пророчество от моего лица.
   Переписал на факты: что работает сейчас, куда лезть не нужно.

Разбор по сейву конкретной игры (`GakkodeG`, 147 значений): денег в игре
**нет** — там разблокировки одежды, тумблеры кастомизации, номер локации,
двери. То есть «выдать деньги» на этой игре бессмысленно, а для остальных
нужен универсальный доступ — чтение всего, что есть.

### Решение шефа

Процесс — можно, но **только для игр, запущенных приложением**. Аргумент:
для тестирования игр (выдать деньги/ресурсы) это необходимо, а для чужих
игр опасно. Старый запрет в AGENTS.md §1 («не лезть в процесс») заменён на
точный: **без мандата не лезем**, мандат — реестр наших запусков.

### Что сделано

`app/transport/unity_rpc/` — новый транспорт:

- `registry.py` — `unity_launches.json` в `%APPDATA%`: pid, exe, папка
  игры, время. `verify_launch(pid, game_dir)` сверяет и запись, и живой
  процесс (exe-путь обязан совпасть). Переживает перезапуск приложения —
  поэтому re-attach возможен. Битый файл не роняет чтение.
- `agent.py` — Frida-агент. Путь до данных:
  `mono_get_root_domain` → `mono_class_vtable` → `mono_vtable_get_static_field_data`
  → **сырой адрес**, дальше читаем/пишем память сами.
  Проверено по экспортам `mono-2.0-bdwgc.dll` (1237 экспортов, все нужные
  точки входа есть). `mono_static_field_get_value` **не экспортируется** —
  поэтому и взяли vtable-путь.
- `injector.py` — attach только после `verify_launch`; `UnityRPCError`
  до `frida.attach` при отсутствии мандата. Ждёт Mono до 60 с, иначе
  честно говорит про IL2CPP/загрузку.

Ключевое решение по безопасности: **агент не вызывает `mono_runtime_invoke`**.
Вызов управляемого кода со стороннего потока роняет Unity. Пишем только
данные, только числовые поля; строки и объекты `writeAt` не принимает.
Раскладку `MonoClassField` не угадываем «в лоб»: имя поля ищем в обоих
слотах и берём похожее на идентификатор; тип тянем экспортированной
`mono_field_get_type`.

### UI

Третья страница «Живая игра» во вкладке «Читы»: класс → поле → тип →
значение, поиск, правка числа. Без канала — честная пустая страница
(«Запустите игру кнопкой из дашборда»).

Найдено и исправлено в процессе: в live-правке вызывался
`json_save.parse_input`, которого там нет (он в `playerprefs`), и не было
разбора bool. Теперь `json_save.as_bool()` (публичный) + разбор по типу.

`UnityModule.features` намеренно остался `{"files", "font"}`: флаг `cheats`
в базе гейтит **автозапуск игры при открытии проекта**, а канал Unity
поднимается по требованию. Комментарий в коде это объясняет.

### Тесты

- `test_unity_new.py` 16 — реестр запусков: чужой pid/folder не проходит,
  битый файл не роняет, запись переживает «перезапуск».
- `test_unity_new.py` 17 — `as_bool`/`parse_input` для типов live-правки.

Шеф собрал и протестировал exe. Итог: **игра перевелась**, но:

| `m_ActionId` | **10** | GUID действия (36 символов) |
| `m_DefaultActionMap` | **1** | имя карты управления |
| `m_Script` | 100 | TextAsset — см. ниже |

### 1. Персонаж не ходил

Подсказка `"action"` в `_TEXT_HINTS` (её добавили ранее с комментарием
«`actionName` хранит подписи взаимодействий для игрока») ловила все три

(имена и с префиксом, и без — в typetree встречаются оба варианта).
Проверено: `actionName` / `m_ActionId` / `m_DefaultActionMap` больше не
извлекаются (0 записей).

### 2. Диалоги ломались

`harvest_textasset` брал **весь файл** TextAsset как одну строку, а
`patch_textasset` подменял `m_Script` целиком. В реальной игре 99 из 100
TextAsset — сценарии по ~28 строк (539 символов в среднем). Переводчик
вправе склеить, потерять или переставить строки — и диалог ломался.

Разметка показала: большинство строк без разделителей (0 запятых на 60%
строк), длинные строки, пустые строки внутри. Не таблицы, но и не
безопасная цель для цельной замены.

Фикс — **построчная** разбивка:
- `harvest_textasset` → `[('m_Script#N', строка_N)]`;
- `patch_textasset_lines` заменяет **только указанные номера строк** —
  пустые строки, отступы и вид перевода строки сохраняются, число строк
  в файле не меняется никогда;
- `json_path` стал `asset://<file>/<pid>/m_Script#7`.

Итог: 8326 записей (было 6397), из них 2029 строчных (было 100 кусков).
Round-trip на копии: json_path сохранён 1990/1990, число строк в файлах не
изменилось, пропусков 0.

Попутно:
- **`_has_sentence` требует пробел** — иначе за предложение сходил
  `com.unity.2d.sprite@1.0.0` из отчёта сборки Unity, конфиг не
  определялся и переводился блобом.
- Таблицы (CSV/TSV) по-прежнему вырезаются `_is_table`.

**Игра восстановлена из бэкапа.** После теста exe в `GakkodeG_Data`
остались переведённые `actionName` и покорёженные TextAsset — это не
лечится «доводом», нужен был откат. `restore_all()` вернул все 14 файлов,
хеши сошлись. Правило в `AGENTS.md`: перед сдачей exe с новым извлечением —
обязательно откатывать игру, иначе следующий круг тестирования начнётся с
битых данных.

### Важное ограничение для продолжения

Эта конкретная игра (`GakkodeG`, AnoKanikousenZ) держит прогресс в одном
JSON с плоскими ключами — правка проходит. Но многие Unity-игры пишут

# ЧАСТЬ 4. ГЛОССАРИЙ ТЕРМИНОВ

| Термин | Значение |
|---|---|
| **Overlay** | перевод поверх запущенной игры, файлы игры не трогаются |
| **Tentacle (щупальце)** | класс живого канала к игре для одного движка |
| **Session** | `GameSession` — одна живая сессия: tentacle + pid + watchdog |
| **CDP** | Chrome DevTools Protocol; хост — Chromium/Electron/NW.js |
| **CDP-fix** | перезапуск игры с `--remote-debugging-port` |
| **MV bridge** | свой HTTP-мост внутри игры (RPG Maker MV без SDK) |
| **typetree** | дерево сериализованных полей Unity-объекта; даёт доступ к полям скриптов |
| **TextAsset / MonoBehaviour** | основные носители текста в Unity-ассетах |
| **Dynamic OS font** | `Font` с непустым `m_FontNames`: Unity рисует системным шрифтом, `m_FontData` игнорирует |
| **PlayerPrefs** | настройки Unity в реестре `HKCU\Software\...` |
| **Rotate-пул** | перебор провайдеров по кругу до первого, кто ответил |
| **BackupStore** | версионированные бэкапы с `manifest.json` |
| **DISABLED_ENGINES** | движки, скрытые от детекта и UI (код и тесты на месте) |
| **Guarded-тест** | тест по реальной игре; если её нет — честный `SKIP` |
