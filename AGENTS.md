# AGENTS.md — рабочий контракт OctopusBridge

Файл — **единственный источник правил** для любого агента (opencode, субагенты,
будущие сессии). Прочитай целиком до первого изменения кода.

---

## 0. Что это за проект

`E:\CODE\OBOB` — **OctopusBridge**, десктопное Windows-приложение на Python/PySide6.
Переводит игры (внутриигровой текст) с разных движков: RPG Maker MV/MZ,
Ren'Py, Twine, Unity (Mono), Wolf RPG, TyranoScript, AjinSyoujyo, HTML.
Плюс «живые» читы (управление запущенной игрой) для движков, где есть канал.

- Лицензия GPL-3.0, публичный репозиторий GitHub: `DezFix/OctopusBridge`.
- Ветка разработки — `main`. Ветка `archive/octopus-8` — замороженный снапшот
  модульной переработки 8.0, откатанной назад. **Не трогать.**
- Полная карта проекта и журнал разработки — `PROJECTS.md`. История —
  `git log`, release-notes — `CHANGELOG.md`.

## 1. Жёсткие запреты (нарушение ломает проект)

1. **Не лезть в процесс игры.** Ни Frida-инъекцией, ни чтением/записью
   памяти, ни хуками в адресном пространстве, ни скан памяти по образцу
   Cheat Engine. Это НЕ техническое ограничение, а решение шефа: живое
   вмешательство выглядит работающим в демо и ломает живую игру в реальном
   использовании.
   Разрешено ТОЛЬКО:
   - файлы игры на диске и её настройки в реестре (PlayerPrefs);
   - сохранения игры (JSON в LocalLow и в папке игры);
   - локальные HTTP/CDP-каналы, которые **сама игра** открывает
     (это используется в RPG Maker / Twine / Ajin / Tyrano).
2. **Не читать и не печатать текст из игр** в отчёт/лог/тест. Диагностика
   строится на числах (`entries`, `candidates`, `objects`, `fonts`) и на
   структурных признаках (имена ассетов, `m_FontNames`, длины). Если нужен
   пример строки — придумать синтетическую.
3. **Не выходить за рамки диска**: то, что игра пишет в файлы/реестр,
   правим безопасно (бэкап + проверка + откат). То, что она держит только
   в памяти процесса — **не наше**. UI обязан честно говорить, что
   значение недоступно, а не молчать.
4. **Не коммитить** без явной просьбы шефа.
5. **Не ломать чужие движки.** Правка Unity не должна ломать RPG Maker/Ren'Py —
   после каждой правки гоняется весь набор тестов (п. 4).

## 2. Архитектурные границы

Слои строго односторонние, Qt живёт только в верхнем:

```
app/core        — чистая логика, БЕЗ Qt. Парсеры, io, translate.
app/engines     — движковые модули: detect/extract/apply + features. БЕЗ Qt.
app/live        — живые сессии: Tentacle, GameSession. Здесь Qt.
app/transport   — код транспортов: cdp/, frida_rpc/.
app/ui          — виджеты, вкладки, i18n.
```

Правила:

- `app/core/<engine>/` — **чистые функции, тестируемые без Qt и без игр**.
  Если функция тянет сеть или пишет на диск — это не `core`.
- `app/engines/base.py` — контракт `EngineModule`. Набор `features` ограничен:
  `{'cheats', 'resources', 'font', 'files'}`. Новый движок = новый класс
  в `app/engines/registry.py::MODULES`.
- `app/ui/engine_tabs.py::build_tabs()` — **единственное** место, где решается,
  какие вкладки у движка. `features` НЕ гейтит вкладки (оно гейтит только
  автозапуск игры, `main_window.py`).
- Честность важнее удобства: если канала нет — UI пишет об этом прямо,
  а не делает вид, что функция работает. Никаких «заглушек, которые
  отчитываются об успехе».

## 3. Роли агентов

### 3.1 opencode — ведущий разработчик (главный по проекту)
- Держит план, принимает решения по архитектуре, разбирает баги от шефа.
- **Все исследования и правки — через субагентов** (Task tool). Агент изучает
  код/данные → opencode собирает план фикса → шеф одобряет → агент правит →
  opencode гоняет тесты и собирает exe.
- Отвечает шефу **по-русски**.
- Обязан держать в порядке `AGENTS.md`, `PROJECTS.md`, `CHANGELOG.md`.

### 3.2 Субагент-исследователь (`explore`)
- Только чтение. Ничего не правит.
- Обязан вернуть отчёт с конкретными `путь:строка`, а не общими словами.

### 3.3 Субагент-исполнитель (`general`)
- Правки по утверждённому плану.
- Обязан добавить/обновить тест на каждый фикс и прогнать `python run_tests.py`.

### 3.4 Субагент-ревьюер
- Проверяет чужой диф на: нарушения границ слоёв, отсутствие теста,
  «честность» сообщений пользователю, ложные обещания в UI.

## 4. Обязательный цикл работы

1. **Воспроизвести.** Найти реальный объект (папку игры) или собрать
   синтетику в `tempfile`. Без воспроизведения фикс не начинается.
2. **Понять механизм.** Ответить: почему именно так? Какой код это решает?
   Где обходной путь? Частая ошибка — чинить симптом (например, «перевод не
   виден»), а не причину.
3. **Синтетика для теста.** Тест не должен требовать игру; реальная игра —
   только в `guarded`-блоке с честным `SKIP`.
4. **Тест сначала падает.** Добавить тест, убедиться, что он ловит баг.
5. **Минимальный фикс.** Не переписывать соседнее.
6. **Прогнать всё:** тесты + линт (ниже).
7. **Записать в `CHANGELOG.md` и `PROJECTS.md`.**

### Команды

```powershell
# Тесты (GUI-тесты требуют offscreen!)
$env:QT_QPA_PLATFORM="offscreen"
python run_tests.py

# Линт (обязательный минимум проекта)
python -m ruff check app --select F821,F401,F811,E9

# Сборка релиза
python build_app.py   # -> dist\OctopusBridge_v7.x.exe
```

`run_tests.py` печатает `ВСЕ 21 ТЕСТОВЫХ ФАЙЛОВ ЗЕЛЁНЫЕ` — это критерий
«ничего не сломано». Любое «УПАЛИ» — сначала выяснить, твоё ли это,
и только потом чинить.

## 4A. Безопасность live-канала Unity (главный риск)

- `attach()` возможен **только** после `registry.verify_launch(pid)` — иначе
  `UnityRPCError` до любого прикосновения к процессу.
- Запись в память рискованнее чтения: цена ошибки — вылет игры. Агент пишет
  **только числовые** поля; строки и объекты `writeAt` не принимает.
- Методы (`mono_runtime_invoke`) агент не вызывает: вызов управляемого кода
  со стороннего потока роняет Unity. Работаем только через
  `mono_vtable_get_static_field_data` — это данные, а не код.
- `send_key` / `screenshot()` для Unity не реализованы и всегда возвращают
  `False` / `None` — врать UI нельзя.
- Канал живёт, пока живёт процесс: при смерти игры `is_attached()` обязан
  стать `False`, а сессия — закрыться.
- Раскладку `MonoClassField` не угадывать «в лоб»: `fieldName` пробует оба
  слота и берёт то, что похоже на идентификатор. Ошибка раскладки =
  запись мусора по случайному адресу.

## 5. Статус движков (важно не путать)

| Движок | `DISABLED_ENGINES` | Файлы | Живые читы | Статус |
|---|---|---|---|---|
| rpgmaker | нет | да | да (CDP + in-game bridge) | рабочий, основной фокус |
| renpy | нет | да | да (агент в игре + Frida как fallback) | рабочий |
| twine | нет | нет (overlay) | да (HTTP + WebSocket) | рабочий |
| unity | нет | да | **да** (Frida + Mono **только для наших процессов**) | рабочий |
| html | нет | нет (overlay) | частично | рабочий |
| tyrano | **да** | да | CDP | отложен |
| ajin | **да** | да | CDP | отложен |
| wolf | **да** | да | нет | отложен |

Вернуть отложенный движок = убрать его ключ из `DISABLED_ENGINES`
в `app/engines/registry.py`. Больше ничего трогать не нужно.

Живые читы Unity **по требованию**: канал поднимается, когда пользователь
сам нажал «Запустить» в дашборде, поэтому `"cheats"` в `UnityModule.features`
не добавляется (иначе игра стартовала бы сама при открытии проекта).

## 5A. Правила для Unity (частые ошибки)

- **`_close_env` — единственный способ закрыть ручку ассета** на Windows.
  Проверять на всех новых путях (см. `app/core/unity/parser.py::_close_env`):
  в UnityPy 1.25.3 поток в `asset.stream`, в старых — в `asset.reader.stream`.
- **TextAsset режется ПОСТРОЧНО** (`m_Script#N`). Целиком файл переводчику
  не отдаём: он ломал диалоги, склеивая и теряя строки. Запись —
  `patch_textasset_lines`, только указанные номера строк.
- **Идентификаторы ввода не переводятся никогда**: `_IDENT_FIELDS`
  (`actionName`, `m_ActionId`, `m_DefaultActionMap`, `m_BindingId`, …).
  Перевод биндинга Unity Input System = персонаж перестаёт ходить.
- **`apply` возвращает контракт `ApplyReport`** (`app/engines/protocol.py`),
  не приватный набор ключей. UI читает `skipped_total` / `skipped_by` /
  `verify_failed` (список строк). Причина пропуска обязательна — иначе
  «применил, а в игре пусто» остаётся без объяснения.
- **Тип исходного значения — закон** в правках JSON-сейвов:
  `bool` не должен стать `0/1`, `float` — стать `int`.
- **Пишем только изменённое.** Перезапись всего контейнера — причина
  «Maximum call stack size exceeded» в Twine; этот урок действует везде.
- Диагностика — числа и структурные признаки, **без текста игры**.
- PlayerPrefs читаем из реестра игры, ветка — по
  `globalgamemanagers` (`companyName`/`productName`), не угадывать.
- **Перед сдачей тестового exe** проверять, что игра не осталась
  переведённой «в никуда»: `restore_all()` возвращает ассеты, если
  следующий этап — переизвлечение.

## 6. Правила кода

- Комментарии и docstring — **по-русски**, объясняют *почему*, не *что*.
- Тексты интерфейса — короткие. Описание не должно повторять заголовок
  и не должно рассказывать про удалённые фичи. Мёртвые ключи `TR(...)`
  удаляются вместе с кодом, который их показывал (проверка — grep по
  `app/` и `tests/`).
- Никаких `TODO`/`заглушка` в коде, который пользователь видит: либо
  работает, либо честно говорит «не поддерживается».
- Диагностика в UI: числа и структурные факты, **без текста игры**.
- Любая запись в файлы игры: `BackupStore` до → `atomic_write_bytes` →
  verify перечитением. Порядок нарушать нельзя (Windows: открытый исходник
  роняет `os.replace` с `WinError 5`).
- UnityPy: грузить по **пути**, не по байтам; ручки закрывать через
  `_close_env` перед записью; verify — загрузкой из байтов.
- Новый движок: `core`-парсер + запись в `registry` + ветка в `build_tabs()`.
